# テスト仕様書 総則

## 1. 目的

本書は Open MES Project（生産ナビ）の各機能モジュールに対するテスト仕様書の総則である。
アプリケーション全体を対象とするが、一度に全モジュールを網羅するのではなく、優先度の高いモジュールから
順次テストケースを作成し、範囲を拡大していく方針を取る（詳細は[3. 作成状況](#3-作成状況)を参照）。

個別モジュールの詳細テストケースは、本ディレクトリ配下に `01_xxx.md` 形式で追加していく。

## 2. 対象モジュール一覧

[主要機能とモジュール](../02_features_modules.md)に記載の各Djangoアプリケーションを対象とする。

| No | モジュール（アプリ名） | 概要 | 実装形態 |
|----|------------------------|------|----------|
| 1 | 在庫管理 (`inventory`) | 在庫、入庫予定/実績、出庫予定、入出庫履歴、受注引当・出庫 | DRF ViewSet (`rest_views.py`) |
| 2 | 生産管理 (`production`) | 製造オーダー、作業指示、資材引当（`MaterialAllocation`）、進捗管理 | Django View + DRF 混在 |
| 3 | 品質管理 (`quality`) | 検査記録の管理・分析 | 要調査 |
| 4 | 設備管理 (`machine`) | 設備の稼働状況・生産実績・資産管理 | 要調査 |
| 5 | マスタ管理 (`master`) | 品目、取引先、倉庫、倉庫ロケーション（レイアウト）等の基本データ | DRF ViewSet |
| 6 | ユーザー管理 (`users`) | ユーザーアカウント・権限・認証 | Django Auth 拡張 |
| 7 | ベース機能 (`base`) | ダッシュボード、共通設定、ナビゲーション等 | Django View |

各モジュールの詳細な機能境界は、コード調査の上で個別テスト仕様書の冒頭に明記する
（例: 「倉庫レイアウトのCRUDは `master` の範囲、レイアウト上への在庫可視化は `inventory` の範囲」等、
一見同じ機能に見えても実装が別アプリに分かれているケースがあるため）。

## 4. テストの種類（[テスト方法](../07_developer_guide/03_testing.md)より）

- **ユニットテスト**: モデルのプロパティ・メソッド、シリアライザのバリデーション等、単体の振る舞いを検証する。
- **統合テスト（機能テスト）**: DRFの `APIClient`／Djangoの `Client` を用いて、エンドポイント単位でリクエスト〜レスポンス
  〜DB状態までの一連の挙動を検証する。カスタムアクション（`@action`）を持つViewSetは、シリアライザ単体では担保できない
  ビュー内の手動バリデーションロジックを直接検証する必要があるため、原則として統合テストを主体とする。
- **E2Eテスト**: 現時点では対象外。開発初期はユニット・統合テストを中心とし、必要に応じて手動検証で補う。

## 5. テストケース記載フォーマット

各モジュールのテスト仕様書は、以下の項目でテストケースを記載する。

| 項目 | 内容 |
|---|---|
| ケースID | `<モジュール略称>-<機能略称>-<連番>` 形式（例: `INV-MOVE-01`） |
| 分類 | 正常系 / 異常系 / 境界値 |
| 対象 | 対象のエンドポイント・関数・メソッド |
| 前提条件 | テスト実行前に必要なデータ状態 |
| 手順・入力 | リクエスト内容やメソッド呼び出し内容 |
| 期待結果 | レスポンスコード、レスポンス内容、DB状態の変化等 |
| 備考 | 実装上の注意点、既知の懸念点等 |

## 6. テスト実行方法とレポート

繰り返し実行して結果を残せるよう、テスト実行とレポート生成をスクリプト化している。

```bash
script/run_tests.sh inventory
```

実行結果は [reports/](./reports/) 配下にMarkdownレポートとしてgit管理下に保存される。手順の詳細・
内部の仕組み・新しいモジュールを追加する際の流れは
[02_running_tests.md](./02_running_tests.md) を参照。

スクリプトを使わず単発で実行したい場合は、従来通り以下でも実行できる(この場合レポートは生成されない)。

```bash
# Docker環境の場合
docker compose exec -it open_mes python3 manage.py test inventory

# ローカル環境の場合
python manage.py test inventory
```

詳細は[テスト方法](../07_developer_guide/03_testing.md)を参照。
