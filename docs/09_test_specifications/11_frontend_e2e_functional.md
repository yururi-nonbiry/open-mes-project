# フロントエンドE2E（画面機能確認: 入庫画面・在庫一覧）

本書は、[Playwright](https://playwright.dev/) による自動テストで検証している、フロントエンドの
画面機能確認について説明する。[10_frontend_e2e.md](./10_frontend_e2e.md)（レスポンシブ表示確認）が
「ボタンが画面幅に収まっていること」だけを対象とするのに対し、本書は画面に表示される内容と
画面操作の結果（一覧の項目、検索、モーダル、登録結果）を対象とする。

## 1. 目的・テスト観点

レスポンシブ表示確認は初期表示時点の静的なボタンのみを検証しており、一覧の明細行に項目が
表示されているかどうかは検証していなかった。そのため、入庫処置画面で「表示設定が未登録のとき、
見出しだけ表示されて明細行の項目が表示されない」不具合（2026-09-30 修正）を検出できなかった。
この反省から、以下の観点を自動検証する。

- 一覧の見出しと明細行が同じ列定義で表示され、各セルに値が表示されること
  （表示設定の有無・内容、ログインユーザーの権限によらないこと）。
- 検索・ステータス絞り込み・ページ送りで、期待した明細が表示されること。
- 入庫・納品の各モーダルが正しい初期値で開き、実行結果が画面とデータの両方に反映されること。
- 入力エラー・通信エラー時に処理が実行されず、利用者に分かる形で表示されること。

バックエンドの業務ロジック（在庫数量の増減、入出庫履歴の記録等）は
[01_inventory.md](./01_inventory.md) の `PO-CRUD-*` / `PO-RECV-*` で検証済みのため、本書では
画面から見える結果と、入庫予定（`PurchaseOrder`）の数量・ステータスまでを確認範囲とする。

## 3. テストデータ

既存の業務データに影響しないよう、E2E専用のマスタと発注番号接頭辞を使用する。

| 種別 | 値 | 作成方法 |
|---|---|---|
| 品番マスタ | `E2E-GR-ITEM` | `script/e2e_goods_receipt_data.py`（事前投入） |
| 倉庫マスタ | `E2E-WH` | 同上 |
| 仕入先マスタ | `E2E-SUP` | 同上 |
| 入庫予定（PC向け） | 発注番号 `E2E-GR-<実行ID>-01`〜`30`、発注数量10、入荷予定日 2000-01-01 | テストが開始時にAPI経由で作成 |
| 入庫予定（スマホ向け） | 発注番号 `E2E-GM-<実行ID>-01`〜`03`、発注数量10、入荷予定日 2000-02-01 | 同上 |
| 入庫予定（在庫照会・入出庫履歴） | 発注番号 `E2E-GI-<実行ID>-01`、開始時に全量入庫して在庫・入出庫履歴を1件以上にする | 同上 |

- 一覧は入荷予定日の昇順で表示されるため、入荷予定日を十分に古い日付にして、検索項目を設定しない
  状態でもテスト用の入庫予定が1ページ目の先頭に並ぶようにしている。
- テスト終了時に、入庫実績の無いテスト用入庫予定は削除される。入庫実績のある入庫予定は削除できない
  仕様（`PO-CRUD-05`）のため、入庫済みのテスト用入庫予定と、それに伴う在庫・入出庫履歴
  （品番 `E2E-GR-ITEM`）は残る。これらは 5. の削除手順でまとめて削除できる。
- 表示設定（`ModelDisplaySetting` の `purchase_order` / `goods_receipt` / `inventory` / `stock_movement`）は
  システム全体で共有される設定のため、PC向けのテストは開始時に現在の設定を退避し、終了時に復元する。
  テストの実行中は入庫処置・在庫照会・入出庫履歴の表示列が一時的に変わるため、他の利用者が同じ環境を
  使用している時間帯は避けること。

## 5. 実行方法

実行環境の前提（ホスト側のNode.js、`db`・`redis`・`backend` の起動、Chromiumの取得）は
[10_frontend_e2e.md](./10_frontend_e2e.md#4-実行方法) と同じ。加えて以下を準備する。

`backend` コンテナは `gunicorn` で起動しておりソースの変更を自動では読み込まないため、バックエンドの
コードを更新した後は、テストの前に `docker compose restart backend` で再起動しておくこと
（古いコードのまま実行すると、追加した項目が画面に反映されない等の見かけ上の失敗になる）。

```bash
# 1. E2E専用マスタの投入(初回、または削除後)
docker compose exec -T backend python manage.py shell < script/e2e_goods_receipt_data.py

# 2. 一般ユーザー(スタッフ権限なし)の作成(初回のみ)。スタッフ権限のユーザーは 10_frontend_e2e.md の e2e_test を使う
docker compose exec -T backend python3 manage.py shell -c "
from users.models import CustomUser
u, _ = CustomUser.objects.get_or_create(custom_id='e2e_general', defaults={'username': 'e2e_general'})
u.set_password('<任意の強いパスワード>')
u.is_staff = False
u.is_superuser = False
u.is_active = True
u.save()
"

# 3. 実行
cd frontend
export E2E_USER_ID='e2e_test'
export E2E_USER_PASSWORD='<e2e_test のパスワード>'
export E2E_GENERAL_USER_ID='e2e_general'
export E2E_GENERAL_USER_PASSWORD='<2.で設定したパスワード>'
npm run test:e2e:functional
```

レスポンシブ表示確認（`npm run test:e2e`）とは別のスイートとして実行される（`playwright.config.ts` の
`E2E_SUITE` による切り替え）。テストが1件でも失敗すると非ゼロの終了コードを返す。

実行結果は、他のテストと同じ方針で以下の固定パスに上書き保存される。画面機能確認のレポートには、
ケースIDと突き合わせられるよう全テストの結果一覧を含めている。

```
docs/09_test_specifications/reports/frontend_functional.md
```

テストデータを削除する場合は以下を実行する（E2E専用の入庫予定・入庫実績・在庫・入出庫履歴・マスタを削除）。

```bash
docker compose exec -T -e E2E_DATA_ACTION=cleanup backend python manage.py shell < script/e2e_goods_receipt_data.py
```

## 6. 既知の懸念事項

1. **【2026-09-30 修正済み】一部入庫の入庫予定を、画面から追加で入庫できない（FE-GR-13 / FE-GRM-05）**
   - バックエンドは一部入庫の入庫予定への追加入庫を受け付ける（`PO-RECV-03`）が、画面側で操作できず、
     分納（複数回に分けた入庫）の2回目以降を画面から登録できなかった。
   - PC向け: `GoodsReceipt.tsx` の「入庫」ボタンが `order.status !== 'pending'` で無効化されていた。
     未入庫・一部入庫のどちらでも、残数量があれば押せるように修正した。
   - スマホ向け: `MobileGoodsReceiptPage.tsx` が `search_status=pending` 固定で取得しており、一部入庫の
     入庫予定が一覧に表示されなかった。入庫予定一覧APIに未入庫・一部入庫の両方を返す
     `search_status=receivable` を追加し（`PO-CRUD-13`）、こちらで取得するように修正した。
2. **【2026-09-30 修正済み】表示設定で仕入先・品番・倉庫を列に選べない（FE-GR-14 / FE-GR-15 / FE-INV-02 / FE-SMH-02）**
   - 「ページ項目表示設定」画面の項目一覧は `model-fields` APIから取得するが、このAPIが外部キーの項目を
     返さないため、入庫予定の仕入先・品番・入庫倉庫、在庫・入出庫履歴の品番・倉庫を一覧表示や検索の対象として
     選択できなかった。
   - `model-fields` APIに `include_relations=true` を追加し、別名を持つ外部キー（`supplier_rel` → `supplier` 等）を
     一覧APIの項目名と同じ別名で返すようにした（`BASE-MODELFIELDS-06/07`）。「ページ項目表示設定」画面と
     各一覧画面はこの指定で取得する。CSVマッピング設定は実フィールド名を前提とするため、従来通り外部キーを
     含めずに取得する。
   - 表示設定APIの `verbose_name` も外部キーの別名から解決するようにした（`BASE-MDS-10`）。
