## デプロイ時の注意（本ブランチの変更で運用に影響するもの）

- inventory 0028 マイグレーション: 在庫の品番・倉庫を NOT NULL にし、「在庫数量 >= 引当済数量 >= 0」の制約を追加する。違反データがあると内容を表示して停止するため、本番データを事前に確認すること。
- `/api/token-auth/` と `POST /api/users/settings/token/`: 一般ユーザーは管理者が APIトークンのポリシーを設定しないと固定トークンを発行できない（既存のトークンでの認証は従来どおり使える）。QR リーダー等のデバイス用ユーザーには、ポリシーの設定が必要。
- マスター（品目・倉庫・BOM・設備・検査項目など）の既存データの変更・削除は管理者のみ（新規登録は一般ユーザーも可能）。検査実績の削除も管理者のみ。
- API の既定権限が IsAuthenticated になった（権限を明示していない公開 API は無い想定）。debug_toolbar は DEBUG=True のときだけ有効。
- CSV 取込: CSV にある列の空欄は値のクリアとして扱う（従来は無視）。在庫数量は在庫調整として入出庫履歴を残す。入庫実績（goods_receipt）と内部受注（INT-）は取込不可。
- 入庫 API: `location: ""` は「棚番なし」を意味する（未指定のときだけ発注・品番マスタの棚番で補う）。
- 管理者によるユーザー作成・パスワード変更もパスワードポリシーで検証される（弱いパスワードは 400）。
- 検査実績の一覧 API はページ分けされた（`data` に加えて `count`・`total_pages`・`summary` を返す）。外部から全件を前提に呼んでいる連携があれば要確認。
- master 0017・production 0017: 品番のデフォルト入庫倉庫・計画の完成品の入庫倉庫に倉庫マスターに無い値があると移行が止まる。事前に本番データを確認すること。
- 旧来の使用部品 API（production/parts-used/）は参照専用になった（登録・変更・削除は 405）。
- 生産計画: 完了・進行中の計画は削除不可。計画を中止すると未出庫の引当は自動で解除される。
- 開発 DB には base 0020・inventory 0028〜0030・master 0016〜0017・production 0017 マイグレーションを適用済み（E2E 実行のため）。開発用 backend コンテナ（gunicorn、自動リロードなし）は本ブランチのコードを読み込むため再起動した。
